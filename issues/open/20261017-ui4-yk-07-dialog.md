# YK-07 — 共通Dialogと開閉・focusの往復

## 1. 目的・範囲

同じDialog props/actionからWebとNativeのmodalを制御する。MVPは一つのmodalで、任意の入れ子overlay engineを先に作らない。

## 2. 実装手順

1. アプリがopenの正規状態を所有し、OpenRequested/DismissRequested/Confirmedと実host結果を分ける。取消/確認/外部closeのreasonと二重通知抑止を実装する。
2. DOMでdialog/showModalの実際の動作を利用する。必要な同期cancel判断、開閉状態の反映、背景、focusの往復、closeイベントの遅延を検証する。
3. NativeはGP-03のscope/semantic APIを使う。背景pointer/key/AX actionがmodalを通り抜けないようにする。
4. 初期focus、Tab/Shift+Tab、Escape、起動元消失、非同期open結果後unmountを処理する。composition中のEscapeは確定済み契約で扱う。
5. common settingsの保存確認へ組み込み、キャンセルで編集値を維持し、確認で一度だけ模擬保存へ進める。

## 3. テスト対象と反例

以下は実施予定。すべて未実行。実装PRで実際のコマンド・candidate SHA・profile・exit code・artifact・PASS/FAIL/未実行を記録する。

1. open→cancel→focus復帰、open→confirm→loading→closeを4 profileで比較する。
2. プログラムcloseとhost closeを重複actionにしない。
3. IME中Escape、起動元の削除、Dialogのunmount、古いrequest結果を検査する。
4. 適切なname/descriptionと実focus/背景抑止を検査する。

## 4. 受入条件

- [ ] 一つのsettings viewでTextFieldとDialogの往復が成立する。
- [ ] 各hostのfocus観測結果が要求と整合する。
- [ ] unsupported modal/AXを成功表示しない。

## 5. 非対象

入れ子Dialog全般、Menu/Popover統合、任意window manager、ブラウザ標準動作の全面再実装。
